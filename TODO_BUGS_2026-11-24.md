## 1. Hole must come after a nonempty decoded prefix (#255)
`an_article_sized_hole_waits_and_resumes_without_decoding_twice`: the fixture archive is about 1.72 MB, so
`archive.len() / 3 / article * article` is 0. The hole then covers the first LZMA2 header, the first run produces no
output or decoder state, and after the repair the test just decodes the whole stream for the first time. It would
still pass if keeping decoder state across a mid-stream hole regressed.
**Fix:** put the hole at an interior article boundary (or shrink the article size for this test) and assert that
some output was produced before the repair (`before > 0`). Check the test fails if the decoder were rebuilt from
the stream start on resume (for example by asserting `redecoded == 0` and `before > 0`).

## 2. Zero-length folder members in the stream layout (#256)
`stream_slots` / `SolidStreamSink::open` for a 7z folder with a zero-length substream before a nonempty member:
both have the same folder offset, so the `f.offset <= offset` filter includes the later nonempty member when the
empty one is requested, and the final-member check returns `InvalidOptions`. Dropping earlier zero-length members
also makes `next_member` reject the hand-off from an empty member to its successor (the expected predecessor is
missing from the layout).
**Fix:** build the layout in folder order up to and including the requested member index (by member index, not
by offset), keeping zero-length predecessors. Tests: leading and middle empty members (see the matching cases in
tests/feed_decoder_7z.rs) through `SolidStreamSink::open` and through `next_member` in-session.

## 3. Keep durable progress when a grouped encrypted refill fails (#257)
In the new grouped encrypted refill path (src/partial/mod.rs around line 978), `group_write` can commit the applied
plaintext when it reaches `group_commit_bytes` or the commit interval. If opening the ciphertext-only group or
retaining its blocks then fails, the bare `?` returns an error without `packed_progress`, although output from this
step is already durable. `fill_packed` reports such progress; `refill_from_packed` must too.
**Fix:** on any error after a successful write, return the error together with the accumulated applied ranges and
current state (the same way `fill_packed` does). Test with a fault injection point (existing test hooks for forced
I/O failures, if present) that fails the ciphertext retention after a group commit, and check the reported
progress matches what is durable after reopen.

## 4. Per-refill time uses the wrong denominator (#257)
`examples/persistent_holes_bench.rs:271` divides refill time by `ranges.len()` (injected hole ranges), but `run`
refills every packed span of every hole report, including cipher-neighbour reports, and already counts those calls
in `refills`. Encrypted and multi-member numbers are overstated.
**Fix:** return the real refill count from `run` and divide by it. Re-run the bench once on F01 to confirm the new
number, and correct the per-refill figures in docs/persistent-partials.md and docs/handoffs/WP-A1.md if they change.
